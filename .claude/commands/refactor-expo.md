# /project:refactor-expo

Expo / React Native のコードを、**現在インストールされているバージョンと構成のベストプラクティス**に従って徹底的にリファクタリングする。

## ステップ 0：プロジェクト構成の自動検出（必須）

リファクタリングを開始する前に、必ず以下を実行してプロジェクトの実際の構成を把握する。

```bash
cat package.json
```

### 0-1. ナビゲーションライブラリの検出

`package.json` の `dependencies` を確認し、使用しているナビゲーションライブラリを特定する。

| 検出するパッケージ | 参照すべき公式ドキュメント |
|---|---|
| `expo-router` | https://docs.expo.dev/router/introduction/ |
| `@react-navigation/native` | https://reactnavigation.org/docs/getting-started |
| `react-native-router-flux` | https://github.com/aksonov/react-native-router-flux |
| `wouter` | https://github.com/molefrog/wouter |
| 上記以外 | package.json に記載のバージョンのGitHub/公式ドキュメントを参照 |

> ⚠️ `expo-router` と `@react-navigation/native` が**両方**入っている場合は、どちらが主体か `app/` や `src/` のエントリポイントを確認して判断すること。

### 0-2. スタイリングライブラリの検出

| 検出するパッケージ | 参照すべき公式ドキュメント |
|---|---|
| `nativewind` | https://www.nativewind.dev/docs |
| `tamagui` | https://tamagui.dev/docs |
| `styled-components` | https://styled-components.com/docs |
| `@shopify/restyle` | https://github.com/Shopify/restyle |
| 上記なし | React Native 標準の `StyleSheet` を使用 → https://reactnative.dev/docs/stylesheet |

### 0-3. その他のコアパッケージのバージョン確認

| パッケージ | 確認すべき公式ドキュメント |
|---|---|
| `expo` | https://docs.expo.dev/versions/latest/ |
| `react-native` | https://reactnative.dev/docs/getting-started |
| `react` | https://react.dev/reference/react |

> ⚠️ ドキュメントを確認せずに前バージョンの知識でリファクタリングしてはならない。APIが変わっている可能性がある。

## 対象ファイル

`$ARGUMENTS` にファイルパスが指定された場合はそのファイルを対象にする。指定がない場合は以下を自動スキャンする：
- `app/` または `src/` ディレクトリ配下の全 `.tsx` / `.ts`
- `components/` ディレクトリ配下の全 `.tsx` / `.ts`
- `hooks/` ディレクトリ配下の全 `.ts`

### ファイル数の確認と分割実行

スキャン前に対象ファイル数を確認する：

```bash
find app src components hooks -name "*.ts" -o -name "*.tsx" 2>/dev/null | wc -l
```

**ファイル数に応じて以下の方針で対応する：**

| ファイル数 | 対応方針 |
|---|---|
| 〜20ファイル | 一括処理してよい |
| 21〜50ファイル | ディレクトリ単位で分割して順番に処理する |
| 51ファイル以上 | 必ず分割する。一括処理を試みてはならない |

**51ファイル以上の場合は、実行前に以下を提示してユーザーに確認を求める：**

```
⚠️ 対象ファイルが多いため、分割して実行することを推奨します。

推奨する実行順序：
1. /project:refactor-expo hooks/
2. /project:refactor-expo components/
3. /project:refactor-expo app/（または src/）

一括実行しますか？それとも上記の順で分割実行しますか？
```

## リファクタリング方針（原則ベース）

以下は**ライブラリ・バージョンに依存しない原則**である。具体的な実装方法は、ステップ0で検出したライブラリの公式ドキュメントに従うこと。

### 1. コンポーネント設計の原則
- 1コンポーネントは1つの責務のみ持つ
- コンポーネントが大きくなりすぎたら分割を検討する
- パフォーマンス最適化（メモ化など）は計測して必要な箇所にのみ適用する
- Props の型定義を明示的に記述し、暗黙の `any` を排除する

### 2. ロジック分離の原則
- UIの描画ロジックとビジネスロジックを分離する
- 再利用可能なロジックはカスタムフックに抽出する
- 副作用は最小化し、クリーンアップを適切に実装する

### 3. スタイリングの原則
- インラインスタイルの散在を避け、スタイル定義を一元化する
- マジックナンバー（数値の直書き）は定数として定義する
- **ステップ0で検出したスタイリングライブラリ**の推奨パターンに統一する
- 複数のスタイリング手法が混在している場合は1つに統一する

### 4. ナビゲーションの原則
- **ステップ0で検出したナビゲーションライブラリ**の現バージョン推奨パターンを採用する
- 型安全なルーティングを確保する（各ライブラリの推奨方法に従う）
- 画面遷移のパターンをプロジェクト全体で統一する
- ディープリンク・モーダルのハンドリングを明示的に実装する
- 異なるナビゲーションライブラリのAPIを混在させない

### 5. エラーハンドリングの原則
- 非同期処理には必ずエラーハンドリングを実装する
- エラーバウンダリを適切な粒度で設置する
- ユーザー向けメッセージと開発者向けログを分離する

### 6. 型安全性の原則
- `any` 型を排除し、`unknown` を使った型ガードで絞り込む
- 外部データ（APIレスポンス等）は受け取り時に型バリデーションを行う

### 7. パフォーマンスの原則
- リスト描画コンポーネントのレンダリング最適化を行う（現バージョンの推奨コンポーネントを使用）
- 画像表示は現バージョンで推奨されるコンポーネントと設定を使用する
- 不要な再レンダリングを特定し除去する

## 禁止事項
- ステップ0の構成検出・ドキュメント参照をスキップしない
- 検出されたライブラリと異なるライブラリのAPIを使用しない
- 既存の機能・挙動を変更しない
- テストが存在する場合、テストが通ることを確認する
- 前バージョンのAPIを「おそらく動くだろう」という推測で使用しない
